# Research: Local tonearm database without scraping around Vinyl Engine anti-bot

## Summary
Build the database with a source-diverse, manual-first pipeline, not a direct Vinyl Engine scraper. Use official manufacturer manuals and brochures first, Wayback captures for dead manufacturer pages second, and a small human-assisted Vinyl Engine gap-fill process only where licensing and account terms allow. Store the working database in SQLite, not CSV, because provenance, conflicting values, incremental updates, and per-field audit trails matter more than raw row count at this scale. [Source](https://sqlite.org/whentouse.html) [Source](https://sqlite.org/onefile.html) [Source](https://www.sqlite.org/appfileformat.html)

## Findings
1. **Do not design around automated Vinyl Engine extraction.** Vinyl Engine’s robots.txt publishes content signals, sets `ai-train=no`, applies a crawl delay, and disallows several paths including library/search endpoints; direct fetches also hit a bot-verification page. Their registration FAQ says some features, including file downloads, are member-only, and access controls were tightened due to abuse. Treat this as a strong signal to avoid bypassing anti-bot protection or bulk scraping authenticated content. [Source](https://www.vinylengine.com/robots.txt) [Source](https://www.vinylengine.com/faq/registration) [Source](https://www.vinylengine.com/faq.shtml)

2. **Vinyl Engine is useful as a field checklist, not the acquisition backbone.** Its tonearm database advertises more than 1,000 entries and explicitly lists the key geometry fields you want: effective mass, effective length, overhang, offset angle, and pivot-to-spindle distance. Its library page says the archive contains manuals, brochures, schematics, and community-contributed documents. That points to the right schema and source hierarchy: capture the same fields, but acquire them from original manuals and brochures wherever possible. [Source](https://www.vinylengine.com/tonearm_database.php) [Source](https://www.vinylengine.com/library.shtml)

3. **Best acquisition strategy: official manuals and brochures first.** Current and archived manufacturer PDFs often include the exact fields needed for a tonearm database. Example search results from official manuals show EMT listing mounting distance, effective length, effective mass, offset angle, and overhang; SME and other manufacturers publish comparable geometry/spec pages in installation manuals. For a few hundred to a few thousand records, a manual extraction workflow from PDFs is practical, especially if you OCR non-searchable scans and only capture the fields you need. [Source](https://emt-tontechnik.ch/uploads/1/4/8/6/148642164/manual-emt-x-tonearm.pdf) [Source](https://sme.co.uk/wp-content/uploads/SME-series-v-instructions.pdf)

4. **Second acquisition tier: manufacturer-site archaeology through the Wayback Machine.** The Internet Archive provides an availability API for checking whether an old manufacturer URL is archived and a CDX API for deeper capture lookup. The Wayback help docs also explain that archived pages may be incomplete, blocked, or missing assets, so every archived datum should store the capture timestamp and archived URL. This is the cleanest repeatable replacement for “scrape Vinyl Engine because the OEM site vanished.” [Source](https://archive.org/help/wayback_api.php) [Source](https://help.archive.org/help/using-the-wayback-machine/)

5. **Third acquisition tier: quarantined secondary sources plus owner-contributed scans.** User-upload mirrors and manual aggregators can help find missing models, but many are derivative, incomplete, or hard to validate. Use them only as lead sources: create a “candidate” record, then require confirmation from an original manual, archived OEM page, catalog scan, or two independent secondary sources before promoting the value to “trusted.” This matters because even geometry values can be inconsistent across reprints and summaries. [Source](https://manuals.plus/m/0a132602976e1df5cd24b9970e0e80c1b8e0dcf3a982c3b7ceb7c24625c37cc6) [Source](https://www.manualslib.com/manual/1449246/Ortofon-Ta-110.html)

6. **Normalization should be field-level, unit-aware, and preserve source wording.** Tonearm geometry is relational: Shure’s geometry paper shows that effective length, overhang, offset angle, and pivot-to-spindle distance are mathematically linked, with overhang derived from effective length minus pivot-to-spindle distance. Normalize numeric values to canonical units (`mm`, `deg`, `g`) while also storing the original text exactly as published. Mark each fact as `stated`, `derived`, `ocr`, or `estimated`, so later users can distinguish a brochure claim from a computed backfill. [Source](https://content-files.shure.com/KnowledgeBaseFiles/phono-cartridge-alignment/tonearm-geometry-and-setup.pdf)

7. **Use a hybrid schema: stable entity tables plus a provenance-rich fact table.** A plain one-row-per-tonearm CSV becomes awkward once different manuals disagree or one source gives only partial specs. Better structure: `manufacturer`, `tonearm_model`, `tonearm_alias`, `source`, and `fact`. In `fact`, store `model_id`, `field_name`, `value_num`, `value_text`, `unit`, `status`, `source_id`, `page_or_locator`, `captured_at`, and optional `confidence`. This lets you keep multiple competing values without losing auditability, then materialize a “current preferred spec” view for analysis. SQLite is well suited because it is single-file, transactional, supports high-level queries, and includes built-in JSON support for sidecar metadata where needed. [Source](https://www.sqlite.org/appfileformat.html) [Source](https://sqlite.org/features.html) [Source](https://www.sqlite.org/json1.html)

8. **Recommend SQLite as the primary store, with CSV exports for interchange.** SQLite is designed for local application storage, data analysis, and single-file portability; it can also import raw CSV and produce CSV outputs. Official SQLite docs explicitly position it as a better application file format than CSV/XML/JSON-style ad hoc files because it is transactional, extensible, and queryable. For this project, SQLite solves three problems CSV does not solve well: multi-source provenance, conflict tracking, and repeatable updates. Keep CSV as export snapshots such as `tonearms.csv`, `facts.csv`, and `sources.csv`. [Source](https://sqlite.org/whentouse.html) [Source](https://sqlite.org/features.html) [Source](https://sqlite.org/onefile.html) [Source](https://www.sqlite.org/appfileformat.html)

9. **A repeatable update workflow is more important than one big import.** Practical workflow: (a) maintain a manufacturer/model target list, (b) check official sites and archived URLs first, (c) save the source artifact locally, (d) OCR if needed, (e) extract into a staging table or CSV, (f) normalize units/names, (g) run geometry consistency checks, (h) review conflicts, then (i) publish a preferred-spec view and CSV export. SQLite supports incremental updates and transactional batches, so monthly or quarterly refreshes are easy without rewriting the whole dataset. Wayback’s APIs make the archive-check step scriptable. [Source](https://archive.org/help/wayback_api.php) [Source](https://sqlite.org/whentouse.html) [Source](https://www.sqlite.org/appfileformat.html)

10. **Legal and ethical guardrails: collect facts, not bulk copies; respect access controls.** Vinyl Engine’s FAQ says downloadable files are provided under its user agreement, and forum guidance from the site owner says users agree not to redistribute files without permission. That means the safer pattern is to store extracted factual metadata, source URLs, timestamps, checksums, and page references, while keeping any downloaded manuals for personal research unless redistribution rights are clear. Do not automate around Cloudflare, login walls, or member-only downloads. If a model is only available on Vinyl Engine, use a manual, low-volume capture process or seek permission. [Source](https://www.vinylengine.com/faq.shtml) [Source](https://www.vinylengine.com/turntable_forum/viewtopic.php?t=45173) [Source](https://www.vinylengine.com/robots.txt)

## Gaps
- I did not verify every major tonearm manufacturer’s current manual archive quality; a brand-by-brand source inventory would improve planning.
- I did not review Vinyl Engine’s full user agreement text beyond publicly surfaced FAQ/forum snippets, so redistribution cautions should be treated as conservative operational guidance, not legal advice.
- I did not benchmark OCR error rates on scanned manuals; next step is a pilot on 25-50 models using mixed PDF quality to estimate manual cleanup cost.
